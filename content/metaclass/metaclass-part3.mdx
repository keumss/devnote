메타클래스가 커지면 여러 생성 훅의 책임, 다중 상속, 추상 기반 클래스와의 조합이 설계의 핵심이 됩니다. 호출 순서를 직접 확인하고, 협력적 `super()`와 결합 메타클래스로 충돌을 해결하며, 런타임 타입 판정과 테스트 상태를 통제합니다.

## __prepare__·__new__·__init__·__call__ 순서 확인하기

클래스를 만들 때와 그 클래스의 인스턴스를 만들 때 호출되는 훅을 구분하려면 실행 순서를 출력해 봅니다. 앞의 세 훅은 클래스 정의 중 실행되고, 메타클래스의 `__call__()`은 완성된 클래스를 호출할 때 실행됩니다.

```python
class LifecycleMeta(type):
    @classmethod
    def __prepare__(mcls, name, bases):
        print('meta __prepare__')
        return {}

    def __new__(mcls, name, bases, namespace):
        print('meta __new__')
        return super().__new__(mcls, name, bases, namespace)

    def __init__(cls, name, bases, namespace):
        print('meta __init__')
        super().__init__(name, bases, namespace)

    def __call__(cls):
        print('meta __call__')
        return super().__call__()


class Service(metaclass=LifecycleMeta):
    def __new__(cls):
        print('instance __new__')
        return super().__new__(cls)

    def __init__(self):
        print('instance __init__')


print('---')
Service()
```

```text
meta __prepare__
meta __new__
meta __init__
---
meta __call__
instance __new__
instance __init__
```

클래스 선언 데이터의 검사와 변환은 메타클래스 `__new__()`에, 생성된 클래스 객체의 후처리는 `__init__()`에, 인스턴스 생성 흐름 변경은 `__call__()`에 둡니다.

## super()로 여러 메타클래스 동작 협력시키기

클래스 표시와 등록처럼 독립된 정책을 조합하려면 각 메타클래스가 `super()`를 호출해야 합니다. 결합 메타클래스의 MRO를 따라 모든 `__new__()`가 차례로 실행됩니다.

```python
class MarkMeta(type):
    def __new__(mcls, name, bases, namespace):
        namespace['marked'] = True
        return super().__new__(mcls, name, bases, namespace)


class RegisterMeta(type):
    registry: list[str] = []

    def __new__(mcls, name, bases, namespace):
        cls = super().__new__(mcls, name, bases, namespace)
        if bases:
            RegisterMeta.registry.append(name)
        return cls


class CombinedMeta(MarkMeta, RegisterMeta):
    pass


class Job(metaclass=CombinedMeta):
    pass


print(Job.marked)
print(RegisterMeta.registry)
```

```text
True
[]
```

`Job`은 첫 기반 클래스라 `bases`가 비어 있어 등록되지 않습니다. 실제 등록 대상인 하위 클래스를 추가하면 `RegisterMeta`에도 전달됩니다.

```python
class EmailJob(Job):
    pass


print(RegisterMeta.registry)
```

```text
['EmailJob']
```

각 훅은 자신이 소비하지 않는 클래스 키워드를 `**kwargs`로 받아 `super()`에 전달해야 다른 정책과 안전하게 조합할 수 있습니다.

## 결합 메타클래스로 다중 상속 충돌 해결하기

서로 다른 메타클래스를 사용하는 두 클래스를 함께 상속하면 Python은 두 후보 모두의 하위 타입인 메타클래스를 요구합니다. 두 정책이 정말 함께 필요하다면 양쪽을 상속한 결합 메타클래스를 명시합니다.

```python
class MetaA(type):
    pass


class MetaB(type):
    pass


class A(metaclass=MetaA):
    pass


class B(metaclass=MetaB):
    pass


class MetaAB(MetaA, MetaB):
    pass


class Combined(A, B, metaclass=MetaAB):
    pass


print(type(Combined).__name__)
print([base.__name__ for base in Combined.__mro__[:3]])
```

```text
MetaAB
['Combined', 'A', 'B']
```

`class Combined(A, B):`처럼 결합 메타클래스를 생략하면 `TypeError: metaclass conflict`가 발생합니다. 결합 순서는 메타클래스들의 협력적 `super()`와 MRO에 맞춰 정합니다.

## ABCMeta를 상속해 추상 계약과 자동 등록 결합하기

추상 메서드가 남은 기반 클래스는 제외하고 완성된 구현만 등록하려면 `ABCMeta`를 확장합니다. `ABCMeta.__new__()`가 만든 `__abstractmethods__`를 확인한 뒤 구체 클래스만 사전에 넣습니다.

```python
from abc import ABCMeta, abstractmethod


class PluginMeta(ABCMeta):
    registry: dict[str, type] = {}

    def __new__(mcls, name, bases, namespace):
        cls = super().__new__(mcls, name, bases, namespace)
        if not cls.__abstractmethods__:
            key = getattr(cls, 'key', None)
            if not isinstance(key, str):
                raise TypeError(f'{name}에 문자열 key가 필요합니다.')
            mcls.registry[key] = cls
        return cls


class Plugin(metaclass=PluginMeta):
    @abstractmethod
    def run(self, value: str) -> str:
        raise NotImplementedError


class UpperPlugin(Plugin):
    key = 'upper'

    def run(self, value: str) -> str:
        return value.upper()


plugin_class = PluginMeta.registry['upper']
print(plugin_class().run('hello'))
```

```text
HELLO
```

`ABC`를 상속하는 클래스의 메타클래스도 `ABCMeta`이므로 사용자 정의 메타클래스가 별도로 `type`만 상속하면 충돌할 수 있습니다. 추상 계약과 결합할 때는 `ABCMeta`의 하위 타입으로 만듭니다.

## __classcell__을 보존해 인수 없는 super() 지원하기

메타클래스가 클래스 네임스페이스를 복사하거나 필터링할 때 메서드가 사용하는 숨은 `__classcell__` 항목을 보존해야 합니다. 단순히 `dict()`로 복사하면 이 항목도 함께 전달됩니다.

```python
class CopyingMeta(type):
    def __new__(mcls, name, bases, namespace):
        copied = dict(namespace)
        return super().__new__(mcls, name, bases, copied)


class Parent(metaclass=CopyingMeta):
    def label(self) -> str:
        return 'parent'


class Child(Parent):
    def label(self) -> str:
        return f'{super().label()}-child'


print(Child().label())
```

```text
parent-child
```

네임스페이스에서 내부 이름을 제거할 때 `__classcell__`까지 버리면 인수 없는 `super()`나 `__class__`를 참조하는 메서드가 클래스 생성 중 `RuntimeError`를 일으킬 수 있습니다. 변환한 매핑을 그대로 `type.__new__()`까지 전달합니다.

## __instancecheck__()로 런타임 판정 기준 바꾸기

상속 관계가 없어도 특정 동작을 가진 객체를 `isinstance()`에서 인정해야 하는 프레임워크 경계에서는 메타클래스의 `__instancecheck__()`를 재정의할 수 있습니다.

```python
class RunnableMeta(type):
    def __instancecheck__(cls, instance):
        return callable(getattr(instance, 'run', None))


class Runnable(metaclass=RunnableMeta):
    pass


class ExternalTask:
    def run(self) -> str:
        return 'done'


task = ExternalTask()
print(isinstance(task, Runnable))
print(task.run())
```

```text
True
done
```

이 판정은 메서드를 추가하거나 정적 타입 정보를 제공하지 않습니다. 애플리케이션 코드의 구조적 타입 계약에는 `Protocol`을 우선하고, 기존 런타임 API의 `isinstance()` 의미를 확장해야 할 때만 사용합니다.

## 지역 메타클래스로 등록 테스트 상태 격리하기

메타클래스의 클래스 변수에 등록 상태를 두면 테스트 실행 순서에 따라 데이터가 남을 수 있습니다. 테스트마다 새 메타클래스를 만드는 팩터리를 사용하면 같은 생성 규칙을 독립된 사전이나 목록으로 확인할 수 있습니다.

```python
def make_registry_meta():
    class LocalRegistryMeta(type):
        registry: list[str] = []

        def __new__(mcls, name, bases, namespace):
            cls = super().__new__(mcls, name, bases, namespace)
            if bases:
                mcls.registry.append(name)
            return cls

    return LocalRegistryMeta


FirstMeta = make_registry_meta()


class FirstBase(metaclass=FirstMeta):
    pass


class Alpha(FirstBase):
    pass


SecondMeta = make_registry_meta()
print(FirstMeta.registry)
print(SecondMeta.registry)
```

```text
['Alpha']
[]
```

프로덕션 코드에서도 등록 상태를 초기화하는 비공개 구현에 의존하기보다 명시적인 레지스트리 객체를 주입하거나 생성 함수를 두면 테스트가 예측 가능해집니다.
