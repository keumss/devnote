첫 세 토픽은 Part 2의 `Hero.team`·`Team.heroes` 모델과 시작 데이터를 사용합니다. 먼저 데이터를 효율적으로 읽고 트랜잭션으로 안전하게 변경한 다음, 다대다 관계·삭제 규칙·집계·계산 속성으로 확장합니다. 다대다 토픽과 `hybrid_property` 토픽은 서로 영향을 주지 않도록 별도 메모리 SQLite 데이터베이스를 사용합니다.

## selectinload와 joinedload로 관련 데이터 미리 읽기

반복문 안에서 `team.heroes`에 접근하면 루프마다 한 번씩 N+1 쿼리 문제가 발생합니다. `selectinload(Team.heroes)`는 관련 모든 Hero를 두 번째 IN 쿼리로 한 번에 묶어 읽어오고, `joinedload(Team.heroes)`는 단일 쿼리에서 LEFT JOIN을 사용합니다. 목록 관계에서는 `selectinload`를 사용하는 것이 보통 예측하기 쉽습니다.

```python
from sqlalchemy.orm import selectinload

with Session(engine) as session:
    statement = select(Team).options(selectinload(Team.heroes)).order_by(Team.name)
    teams = session.scalars(statement).all()
    lines = [f'{team.name}: {[hero.name for hero in team.heroes]}' for team in teams]

print('\n'.join(lines))
```

```text
Preventers: ['Rusty-Man']
Z-Force: ['Deadpond']
```

`joinedload`도 동작하지만, 컬렉션 관계에 사용하면 조인 결과 부모 행이 중복되어 `.unique().all()`을 명시해야 합니다. 목록(list) 관계에서는 `selectinload`가 예측하기 편합니다.

## session.begin으로 여러 변경을 하나의 트랜잭션으로 묶기

Hero를 다른 팀으로 옮기면서 팀의 본부 이름도 동시에 수정하는 것처럼, 여러 변경이 전부 성공하거나 전부 취소되어야 할 때 사용합니다. `session.begin()` 컨텍스트 매니저를 쓰면 성공 시 자동 커밋되고 예외 발생 시 자동 롤백됩니다.

```python
with Session(engine) as session:
    with session.begin():
        hero = session.scalars(select(Hero).where(Hero.name == 'Spider-Boy')).one()
        team = session.scalars(select(Team).where(Team.name == 'Z-Force')).one()
        hero.team = team
        team.headquarters = 'New Sister Margaret\'s Bar'

with Session(engine) as session:
    hero = session.scalars(select(Hero).where(Hero.name == 'Spider-Boy')).one()
    print(hero.team.name if hero.team else None)
    print(hero.team.headquarters if hero.team else None)
```

```text
Z-Force
New Sister Margaret's Bar
```

`begin()` 블록이 정상적으로 종료되면 자동으로 변경을 데이터베이스에 확정(commit)하고 예외가 발생하면 롤백합니다. 여러 행을 변경하는 서비스 함수에서 주로 사용합니다.

## Association 테이블로 Hero-Power 다대다 관계 만들기

Hero와 Power 간 연결 외에 추가 데이터가 필요 없는 단순한 다대다 관계입니다. 모델 클래스 대신 `sqlalchemy.Table`로 연관 테이블을 직접 만듭니다.

```python
from sqlalchemy import Column, ForeignKey, String, Table, create_engine
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship, Session


class ManyBase(DeclarativeBase):
    pass


hero_power_table = Table(
    'hero_power',
    ManyBase.metadata,
    Column('hero_id', ForeignKey('m2m_hero.id'), primary_key=True),
    Column('power_id', ForeignKey('power.id'), primary_key=True),
)


class Power(ManyBase):
    __tablename__ = 'power'

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(100))
    heroes: Mapped[list['M2MHero']] = relationship(secondary=hero_power_table, back_populates='powers')


class M2MHero(ManyBase):
    __tablename__ = 'm2m_hero'

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(100))
    powers: Mapped[list[Power]] = relationship(secondary=hero_power_table, back_populates='heroes')


m2m_engine = create_engine('sqlite://')
ManyBase.metadata.create_all(m2m_engine)

with Session(m2m_engine) as session:
    flight = Power(name='Flight')
    strength = Power(name='Super Strength')
    hero = M2MHero(name='Rusty-Man', powers=[flight, strength])
    session.add(hero)
    session.commit()

with Session(m2m_engine) as session:
    hero = session.scalars(select(M2MHero)).one()
    print(hero.name, [p.name for p in hero.powers])
```

```text
Rusty-Man ['Flight', 'Super Strength']
```

`Table()`로 연결용 테이블만 만들고 `relationship`의 `secondary` 매개변수에 이를 지정합니다. 연결 자체에 날짜나 역할 등 추가 정보가 필요 없을 때 적합합니다.

## Association Object로 다대다에 추가 데이터 붙이기

Hero가 Project에 참여할 때 역할(role)이나 날짜 같은 추가 정보가 필요하다면, 연관 객체(Association Object)를 뜻하는 모델 클래스를 사용해야 합니다.

```python
class AssocBase(DeclarativeBase):
    pass


class HeroProjectLink(AssocBase):
    __tablename__ = 'hero_project_link'

    hero_id: Mapped[int] = mapped_column(ForeignKey('assoc_hero.id'), primary_key=True)
    project_id: Mapped[int] = mapped_column(ForeignKey('project.id'), primary_key=True)
    role: Mapped[str] = mapped_column(String(50))
    hero: Mapped['AssocHero'] = relationship(back_populates='project_links')
    project: Mapped['Project'] = relationship(back_populates='hero_links')


class Project(AssocBase):
    __tablename__ = 'project'

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(100))
    hero_links: Mapped[list[HeroProjectLink]] = relationship(back_populates='project')


class AssocHero(AssocBase):
    __tablename__ = 'assoc_hero'

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(100))
    project_links: Mapped[list[HeroProjectLink]] = relationship(back_populates='hero')


assoc_engine = create_engine('sqlite://')
AssocBase.metadata.create_all(assoc_engine)

with Session(assoc_engine) as session:
    hero = AssocHero(name='Rusty-Man')
    project = Project(name='Rescue')
    session.add_all([hero, project])
    session.commit()

    session.add(HeroProjectLink(hero_id=hero.id, project_id=project.id, role='lead'))
    session.commit()

with Session(assoc_engine) as session:
    link = session.scalars(select(HeroProjectLink)).one()
    print(link.hero.name, link.project.name, link.role)
```

```text
Rusty-Man Rescue lead
```

단순 연결은 `secondary`로 충분하지만, 연결 링크 자체에 업무 정보(역할, 날짜, 중요도 등)가 필요할 때는 별도 모델을 만드는 Association Object 패턴을 씁니다.

## cascade로 Team 삭제 시 Hero 함께 지우기

Team이 삭제될 때 그 팀에 속한 Hero들도 함께 삭제되게 하려면 ORM과 DB 양쪽에 삭제 규칙을 명시합니다.

기존 Part 2의 모델 선언을 다음과 같이 수정합니다.

```python
# Team.heroes 변경
heroes: Mapped[list['Hero']] = relationship(back_populates='team', cascade='all, delete-orphan')

# Hero.team_id 변경
team_id: Mapped[int | None] = mapped_column(ForeignKey('team.id', ondelete='CASCADE'), default=None)
```

변경된 규칙을 적용한 새로운 엔진과 데이터에서 확인합니다.

```python
with Session(engine) as session:
    team = session.scalars(select(Team).where(Team.name == 'Z-Force')).one()
    session.delete(team)
    session.commit()

with Session(engine) as session:
    heroes = session.scalars(select(Hero).where(Hero.name == 'Deadpond')).all()

print(heroes)
```

```text
[]
```

`cascade='all, delete-orphan'`은 ORM 쪽의 삭제 연쇄를 담당하고, `ondelete='CASCADE'`는 DB 레벨의 제약 조건 삭제를 담당합니다. 만약 팀 삭제 시 Hero 기록은 남겨야 한다면 CASCADE 대신 SET NULL 정책을 사용합니다.

## func와 group_by로 팀별 Hero 수 집계하기

여러 행의 데이터를 모아 계산할 때 사용합니다. 원본 Part 2 데이터를 사용합니다.

```python
from sqlalchemy import func

with Session(engine) as session:
    statement = (
        select(Team.name, func.count(Hero.id).label('hero_count'))
        .join(Hero, Hero.team_id == Team.id)
        .group_by(Team.name)
        .having(func.count(Hero.id) >= 1)
        .order_by(Team.name)
    )
    rows = session.execute(statement).all()

print([(name, count) for name, count in rows])
```

```text
[('Preventers', 1), ('Z-Force', 1)]
```

`func.count()`는 SQL의 `COUNT()` 함수와 같고, `label()`은 결과 컬럼에 이름을 부여합니다. `having()`은 그룹화 후의 조건 필터링에 씁니다. 컬럼을 여러 개 선택한 경우 `scalars()`가 아닌 `execute()`를 써서 Row 튜플로 반환받습니다.

## hybrid_property로 모델에 계산 속성 추가하기

Python 인스턴스에서 일반 속성처럼 쓰면서 SQL 쿼리의 필터 조건으로도 동시에 쓸 수 있는 속성입니다.

```python
from sqlalchemy import String, case, create_engine
from sqlalchemy.ext.hybrid import hybrid_property
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column


class HybridBase(DeclarativeBase):
    pass


class HybridHero(HybridBase):
    __tablename__ = 'hybrid_hero'

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(100))
    age: Mapped[int | None] = mapped_column(default=None)

    @hybrid_property
    def is_adult(self) -> bool:
        return self.age is not None and self.age >= 18

    @is_adult.expression
    @classmethod
    def is_adult(cls):
        return case((cls.age >= 18, True), else_=False)


hybrid_engine = create_engine('sqlite://')
HybridBase.metadata.create_all(hybrid_engine)

with Session(hybrid_engine) as session:
    session.add_all([
        HybridHero(name='Rusty-Man', age=48),
        HybridHero(name='Spider-Boy', age=16),
        HybridHero(name='Deadpond'),
    ])
    session.commit()

with Session(hybrid_engine) as session:
    adults = session.scalars(select(HybridHero).where(HybridHero.is_adult == True)).all()
    print([hero.name for hero in adults])

    boy = session.scalars(select(HybridHero).where(HybridHero.name == 'Spider-Boy')).one()
    print(boy.is_adult)
```

```text
['Rusty-Man']
False
```

`@hybrid_property`는 Python 객체에서 실행되고, `@is_adult.expression`은 WHERE 절에서 SQL 표현식으로 변환됩니다. Python 코드와 데이터베이스 쿼리 양쪽에서 동작해야 하는 재사용 가능한 업무 규칙에 사용합니다.

공식 SQLAlchemy [관계 로딩 전략](https://docs.sqlalchemy.org/en/20/orm/queryguide/relationships.html), [세션·트랜잭션](https://docs.sqlalchemy.org/en/20/orm/session_transaction.html), [다대다 관계](https://docs.sqlalchemy.org/en/20/orm/basic_relationships.html#many-to-many), [하이브리드 속성](https://docs.sqlalchemy.org/en/20/orm/extensions/hybrid.html)을 기준으로 Python 3.12 예제를 구성했습니다.
