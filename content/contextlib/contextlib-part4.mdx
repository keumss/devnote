`db_manager.py` 하나로 여러 데이터베이스 연결을 열고, 트랜잭션 안에서 쿼리를 실행하며, 실패 시 안전하게 정리하는 도구를 만듭니다. 목표는 동적 개수의 연결을 `ExitStack`으로 관리하고, `@contextmanager`로 트랜잭션 래퍼를 구현하며, 연결 실패 시 이전에 열린 모든 연결을 자동으로 닫는 것입니다. 아래 코드 블록을 순서대로 같은 파일에 추가합니다.

## 임포트와 가상 데이터베이스 연결 클래스 준비하기

```python
import sys
from contextlib import contextmanager, ExitStack, suppress

class Connection:
    def __init__(self, name: str, *, fail: bool = False):
        if fail:
            raise ConnectionError(f"[{name}] 연결 실패!")
        self.name = name
        print(f"[{self.name}] 연결 열림")

    def close(self):
        print(f"[{self.name}] 연결 닫힘")

    def execute(self, query: str):
        print(f"[{self.name}] 쿼리 실행: {query}")
        return {"status": "success"}

    def begin(self):
        print(f"[{self.name}] 트랜잭션 시작")

    def commit(self):
        print(f"[{self.name}] 트랜잭션 커밋")

    def rollback(self):
        print(f"[{self.name}] 트랜잭션 롤백")
```

이 `Connection` 클래스는 자체적인 컨텍스트 매니저 인터페이스(`__enter__`, `__exit__`)를 가지지 않으며, 실제 데이터베이스 연결 객체의 동작을 시뮬레이션하기 위해 작성되었습니다. `fail=True`가 주어지면 초기화 시점에서 `ConnectionError`를 발생시켜 연결 실패 상황을 재현합니다.

## `@contextmanager`로 트랜잭션 래퍼 만들기

```python
@contextmanager
def transaction(conn: Connection):
    conn.begin()
    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise
```

호출자가 `with transaction(conn):` 블록 안에서 쿼리를 실행할 때, 예외가 발생하지 않으면 자동으로 `commit()`이 호출됩니다. 중간에 예외가 발생하면 즉시 `except` 블록을 타면서 `rollback()`을 실행한 뒤 호출자에게 예외를 다시 던집니다.

## `ExitStack`으로 여러 연결을 일괄 열기

```python
@contextmanager
def open_connections(names: list[str]):
    with ExitStack() as stack:
        conns = []
        for name in names:
            # 예제를 위해 'analytics' 이름이 들어오면 강제로 연결 실패를 발생시킵니다.
            fail_sim = (name == "analytics")
            conn = Connection(name, fail=fail_sim)
            stack.callback(conn.close)
            conns.append(conn)
        yield conns
```

`ExitStack`은 등록된 콜백 함수들을 스택에 쌓아둡니다. `Connection` 인스턴스가 정상적으로 생성되면 `stack.callback(conn.close)`를 통해 자원 정리 함수를 등록합니다. 루프를 돌던 중 하나라도 실패하여 예외가 발생하면, `with ExitStack()` 블록을 빠져나가면서 이전에 등록해 둔 `close()` 콜백들이 역순으로 자동 실행됩니다. 

## main으로 연결 사용과 오류 처리 연결하기

```python
def main() -> int:
    # 명령줄 인수로 데이터베이스 이름 목록을 받거나, 없으면 기본값을 사용합니다.
    names = sys.argv[1:] if len(sys.argv) > 1 else ["users", "orders"]
    
    try:
        with open_connections(names) as conns:
            for conn in conns:
                with transaction(conn):
                    conn.execute("SELECT 1")
    except (ConnectionError, ValueError) as e:
        print(f"오류 발생: {e}", file=sys.stderr)
        return 1
        
    return 0

if __name__ == '__main__':
    raise SystemExit(main())
```

`open_connections()`가 반환한 여러 개의 연결을 순회하면서 각각 트랜잭션을 실행합니다. 만약 연결 중 하나라도 `ConnectionError`를 발생시키면 `except` 구문에서 잡아내어 프로그램이 안전하게 종료 코드 1을 반환합니다.

```bash

```

```text
[users] 트랜잭션 커밋
[orders] 트랜잭션 시작
[orders] 쿼리 실행: SELECT 1
[orders] 트랜잭션 커밋
[orders] 연결 닫힘
[users] 연결 닫힘
```

이번에는 `analytics` 데이터베이스를 추가하여 의도적인 실패 시나리오를 실행합니다.

```bash
python db_manager.py users orders analytics
```

```text
[users] 연결 열림
[orders] 연결 열림
오류 발생: [analytics] 연결 실패!
[orders] 연결 닫힘
[users] 연결 닫힘
```

`ExitStack`이 연결을 역순으로 정리하고, `@contextmanager`가 트랜잭션의 성공·실패를 분기하며, 하나의 연결 실패가 이전에 열린 모든 연결을 안전하게 닫습니다.


공식 Python [contextlib 문서](https://docs.python.org/3.12/library/contextlib.html)의 `contextmanager`, `ExitStack`, `suppress` 동작을 기준으로 Python 3.12 예제를 구성했습니다.
