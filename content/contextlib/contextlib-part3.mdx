## `ExitStack`으로 여러 컨텍스트 매니저를 한 with에서 관리하기

관리해야 할 리소스의 개수가 동적(사용자 입력, 설정 파일 등에 의해 결정됨)일 때 유용합니다.

```python
from contextlib import ExitStack

filenames = ["file1.txt", "file2.txt", "file3.txt"]

# 편의상 파일 쓰기를 가정
with ExitStack() as stack:
    files = [stack.enter_context(open(fname, 'w')) for fname in filenames]
    
    for f in files:
        f.write("Hello")
        
    print(f"{len(files)}개의 파일이 열렸습니다.")
```

```text
3개의 파일이 열렸습니다.
```

- **핵심 규칙**: 
  - `stack.enter_context()`는 전달된 컨텍스트 매니저의 `__enter__()` 결과를 반환하며, `__exit__()`은 스택에 등록됩니다.
  - 리소스 중 하나를 여는 데 실패하더라도, 이전에 성공적으로 열린 리소스들은 모두 자동으로 안전하게 닫힙니다.
  - `__enter__`는 `ExitStack` 인스턴스 자신을 반환합니다.

## `ExitStack.callback()`으로 정리 함수 등록하기

정리(cleanup) 로직이 컨텍스트 매니저 형태가 아니라 일반 함수일 때 사용합니다.

```python
from contextlib import ExitStack

def cleanup_action(name):
    print(f"Cleaning up {name}")

with ExitStack() as stack:
    # 1. 메서드 호출 형태
    stack.callback(cleanup_action, "Resource A")
    
    # 2. 데코레이터 형태
    @stack.callback
    def inline_cleanup():
        print("Cleaning up Inline")
        
    print("Doing work...")
```

```text
Doing work...
Cleaning up Inline
Cleaning up Resource A
```

- **핵심 규칙**:
  - 콜백은 스택에 등록된 역순(LIFO)으로 실행됩니다.
  - 일반 콜백 함수는 예외 정보를 인자로 받지 않으므로, 컨텍스트 내에서 발생한 예외를 억제(suppress)할 수 없습니다.

## `ExitStack.pop_all()`로 정리 책임을 이전하기

"전부 성공하거나 전부 취소되거나(all or nothing)" 패턴을 구현할 때 사용합니다. 리소스를 모두 연 후 검증하고, 성공 시 소유권(정리 책임)을 호출자에게 넘깁니다.

```python
from contextlib import ExitStack

def open_multiple_files(filenames):
    with ExitStack() as stack:
        files = [stack.enter_context(open(fname, 'w')) for fname in filenames]
        # 모든 파일이 성공적으로 열리면 정리 책임을 이전함
        return stack.pop_all(), files

# 사용 예
stack, files = open_multiple_files(["a.txt", "b.txt"])
try:
    print("Files are open and ready.")
finally:
    stack.close() # 호출자가 최종적으로 닫을 책임을 짐
```

```text
Files are open and ready.
```

- **핵심 규칙**:
  - `pop_all()`은 현재까지 등록된 모든 컨텍스트 매니저와 콜백을 담은 새로운 `ExitStack`을 반환하며, 기존 스택은 비워집니다.
  - 리소스를 여는 도중 하나라도 실패하면, `pop_all()`이 호출되기 전이므로 `ExitStack`이 이전에 열린 리소스들을 모두 닫아 누수를 방지합니다.

## `AbstractContextManager`로 프로토콜 명시하기

클래스 기반 컨텍스트 매니저를 작성할 때, 컨텍스트 매니저 프로토콜을 명시적으로 따르도록 강제하고 싶을 때 사용합니다.

```python
from contextlib import AbstractContextManager

class MyResource(AbstractContextManager):
    def __init__(self, name):
        self.name = name
        
    # __enter__는 AbstractContextManager에 의해 기본적으로 self를 반환하도록 구현되어 있음
    
    def __exit__(self, exc_type, exc_value, traceback):
        print(f"Releasing {self.name}")
        return False # 예외를 억제하지 않음

with MyResource("DB Connection") as res:
    print(f"Using {res.name}")
```

```text
Using DB Connection
Releasing DB Connection
```

- **핵심 규칙**:
  - `AbstractContextManager`를 상속받으면 `__enter__`가 기본적으로 `self`를 반환하도록 제공됩니다.
  - `__exit__` 메서드는 추상 메서드이므로 반드시 구현해야 합니다.
  - 비동기 버전을 위해서는 `AbstractAsyncContextManager`를 사용할 수 있습니다.

## 단일 사용·재사용·재진입 컨텍스트 매니저 차이

컨텍스트 매니저의 인스턴스를 여러 번 혹은 중첩해서 사용할 수 있는지에 따라 세 가지로 분류할 때 개념적으로 알아두어야 합니다.

- **단일 사용(Single use)**: `@contextmanager`로 만든 함수나 파일 객체처럼 한 번만 사용할 수 있습니다. 다시 사용하려 하면 오류가 발생합니다.
- **재사용 가능(Reusable)**: `ExitStack`처럼 순차적으로 여러 번 사용할 수 있지만, 중첩해서(nested) 사용할 수는 없습니다.
- **재진입 가능(Reentrant)**: `suppress`, `redirect_stdout`, `chdir` 등과 같이 동일한 인스턴스를 중첩해서 안전하게 사용할 수 있습니다.

```python
import sys
from contextlib import redirect_stdout, contextmanager

# 1. 단일 사용 예시 (실패 케이스)
@contextmanager
def my_cm():
    yield
    
cm = my_cm()
with cm:
    pass
try:
    with cm: # 두 번째 사용
        pass
except RuntimeError as e:
    print(f"Error: {e}")

# 2. 재진입 가능 예시
reentrant_cm = redirect_stdout(sys.stdout)
with reentrant_cm:
    with reentrant_cm: # 중첩 사용 가능
        print("Nested redirect works")
```

```text
Error: generator didn't yield
Nested redirect works
```

- **핵심 규칙**: 안전성을 위해 컨텍스트 매니저는 미리 인스턴스를 만들어두기보다 `with` 구문 헤더에서 직접 생성하는 것이 좋습니다.

## `@contextmanager`에서 yield 누락 시 오류 이해하기

`@contextmanager`로 데코레이션된 제너레이터가 값을 `yield` 하지 않거나 여러 번 `yield` 할 때 발생하는 문제를 방지하기 위해 알아야 합니다.

```python
from contextlib import contextmanager

@contextmanager
def no_yield():
    print("Setup")
    # yield 누락
    print("Teardown")

try:
    with no_yield():
        print("Inside with")
except RuntimeError as e:
    print(f"Error: {e}")
```

```text
Setup
Teardown
Error: generator didn't yield
```

- **핵심 규칙**:
  - 데코레이션된 함수는 반드시 한 번만 `yield` 해야 합니다.
  - `yield`가 없으면 `RuntimeError: generator didn't yield`가 발생합니다.
  - 두 번 이상 `yield` 하면, `__exit__`이 호출될 때 두 번째 `yield`를 만나 `RuntimeError: generator didn't stop`이 발생합니다.

공식 Python [contextlib 문서](https://docs.python.org/3.12/library/contextlib.html)의 `ExitStack`, `AbstractContextManager`, 재진입·재사용 규칙을 기준으로 Python 3.12 예제를 구성했습니다.
