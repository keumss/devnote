블로그 포스트에 사진 파일을 업로드하고, API가 커지면 라우터로 분리해야 합니다. 이 노트에서는 `UploadFile`로 이미지를 받아 서버에 저장하고, `StaticFiles`로 서빙하며, `APIRouter`로 포스트와 이미지 경로를 나누고, 포스트·작성자·사진의 관계 API를 만듭니다.

## UploadFile로 이미지 파일 업로드 받기

블로그 포스트에 사진을 첨부할 때 클라이언트가 `multipart/form-data`로 보낸 파일을 `UploadFile`로 받습니다. `UploadFile`은 큰 파일도 메모리에 전부 올리지 않고 스트리밍으로 처리합니다.

```python
import shutil
from pathlib import Path

from fastapi import FastAPI, UploadFile

app = FastAPI()
UPLOAD_DIR = Path('uploads')
UPLOAD_DIR.mkdir(exist_ok=True)


@app.post('/images', status_code=201)
async def upload_image(file: UploadFile) -> dict:
    dest = UPLOAD_DIR / file.filename
    with dest.open('wb') as buf:
        shutil.copyfileobj(file.file, buf)
    return {'filename': file.filename, 'content_type': file.content_type}
```

```text
POST /images (file=photo.jpg)
201 {"filename":"photo.jpg","content_type":"image/jpeg"}
```

`file.filename`은 클라이언트가 보낸 원본 이름이고, `file.file`은 읽기 가능한 파일 객체입니다. 실제 서비스에서는 파일명 충돌을 막기 위해 UUID 등으로 저장 이름을 바꿉니다.

## list[UploadFile]로 여러 이미지 동시 업로드하기

포스트에 사진 여러 장을 한 번에 첨부할 때 `list[UploadFile]`로 선언합니다. 같은 필드 이름으로 여러 파일이 전송됩니다.

```python
@app.post('/images/bulk', status_code=201)
async def upload_images(files: list[UploadFile]) -> dict:
    saved = []
    for file in files:
        dest = UPLOAD_DIR / file.filename
        with dest.open('wb') as buf:
            shutil.copyfileobj(file.file, buf)
        saved.append(file.filename)
    return {'uploaded': saved, 'count': len(saved)}
```

```text
POST /images/bulk (files=[a.jpg, b.jpg, c.jpg])
201 {"uploaded":["a.jpg","b.jpg","c.jpg"],"count":3}
```

업로드 개수를 제한하려면 엔드포인트 안에서 `len(files)`를 검사합니다. 파일 크기 제한은 배포 환경의 리버스 프록시(nginx 등)에서도 함께 설정합니다.

## StaticFiles로 업로드된 이미지 서빙하기

업로드한 이미지를 브라우저에서 접근할 때 `StaticFiles`를 별도 경로에 마운트합니다. `StaticFiles`는 파일 시스템의 디렉터리를 URL 경로에 연결하는 ASGI 애플리케이션입니다.

```python
from fastapi.staticfiles import StaticFiles

app.mount('/static/uploads', StaticFiles(directory='uploads'), name='uploads')
```

마운트 뒤 `http://localhost:8000/static/uploads/photo.jpg`로 이미지에 접근할 수 있습니다.

```text
GET /static/uploads/photo.jpg → 200 (이미지 파일)
GET /static/uploads/없는파일.jpg → 404
```

첫 번째 `/static/uploads`는 브라우저가 요청할 URL이고, `directory`는 서버가 파일을 찾을 디렉터리입니다. API 경로(`/posts`, `/images`)와 정적 파일 경로(`/static/...`)가 겹치지 않도록 prefix를 구분합니다.

## Form과 File을 함께 받아 포스트와 이미지 동시 생성하기

HTML 폼이나 모바일 앱에서 제목·본문과 파일을 한 요청으로 보낼 때 `Form()`과 `UploadFile`을 같은 엔드포인트에 선언합니다.

```python
from fastapi import Form, UploadFile


@app.post('/posts/with-image', status_code=201)
async def create_post_with_image(
    title: str = Form(),
    content: str = Form(),
    thumbnail: UploadFile | None = None,
) -> dict:
    thumbnail_url = None
    if thumbnail:
        dest = UPLOAD_DIR / thumbnail.filename
        with dest.open('wb') as buf:
            shutil.copyfileobj(thumbnail.file, buf)
        thumbnail_url = f'/static/uploads/{thumbnail.filename}'
    return {'title': title, 'content': content, 'thumbnail_url': thumbnail_url}
```

`Form`과 `UploadFile`은 `multipart/form-data`로 전송되므로 JSON body(`post: BlogPostCreate`)와 동시에 사용할 수 없습니다. JSON으로 메타데이터를 보내고 파일을 별도 요청으로 올리는 방식도 자주 쓰입니다. 이 제약은 HTTP 프로토콜의 `Content-Type` 규칙에서 옵니다.

## APIRouter로 포스트·이미지 라우터 분리하기

API가 커지면 모든 경로를 `app`에 직접 등록하는 대신 관심사별로 라우터를 나눕니다. `APIRouter`에 `prefix`와 `tags`를 선언하면 경로 그룹화와 API 문서 정리가 함께 됩니다.

```python
from fastapi import APIRouter

post_router = APIRouter(prefix='/posts', tags=['posts'])
image_router = APIRouter(prefix='/images', tags=['images'])


@post_router.get('/')
def list_posts() -> list[dict]:
    return []


@post_router.get('/{post_id}')
def get_post(post_id: int) -> dict:
    return {'post_id': post_id}


@image_router.post('/', status_code=201)
async def upload_image(file: UploadFile) -> dict:
    return {'filename': file.filename}


app.include_router(post_router)
app.include_router(image_router)
```

`@post_router.get('/')`는 prefix와 합쳐져 `GET /posts/`가 됩니다. `tags`는 `/docs`에서 경로를 그룹으로 묶어 보여 줍니다. 실제 프로젝트에서는 `routers/posts.py`, `routers/images.py`처럼 파일로 나누고 `app.include_router()`로 연결합니다.

## Relationship과 response_model로 포스트·작성자·사진 관계 API 만들기

블로그 포스트에 한 명의 작성자와 여러 장의 사진이 연결될 때 SQLModel의 `Relationship`과 `foreign_key`로 관계를 선언합니다. 입출력 모델을 분리해 목록과 상세가 필요한 필드만 응답합니다.

```python
from sqlmodel import Field, Relationship, SQLModel


class Author(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    name: str = Field(index=True)
    posts: list['BlogPost'] = Relationship(back_populates='author')


class BlogPost(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    title: str = Field(index=True)
    content: str
    thumbnail_url: str | None = None
    author_id: int = Field(foreign_key='author.id', index=True)
    author: Author = Relationship(back_populates='posts')
    images: list['PostImage'] = Relationship(back_populates='post')


class PostImage(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    url: str
    alt_text: str
    position: int
    post_id: int = Field(foreign_key='blogpost.id', index=True)
    post: BlogPost = Relationship(back_populates='images')
```

입력과 응답 모델을 분리합니다.

```python
class PostImageCreate(SQLModel):
    url: str
    alt_text: str


class BlogPostCreate(SQLModel):
    title: str
    content: str
    thumbnail_url: str | None = None
    images: list[PostImageCreate] = Field(default_factory=list)


class AuthorPublic(SQLModel):
    id: int
    name: str


class PostImagePublic(SQLModel):
    id: int
    url: str
    alt_text: str
    position: int


class BlogPostListItem(SQLModel):
    id: int
    title: str
    thumbnail_url: str | None
    author: AuthorPublic


class BlogPostDetail(BlogPostListItem):
    content: str
    images: list[PostImagePublic]
```

`BlogPostCreate`에 `author_id`를 넣지 않습니다. 작성자 식별은 인증에서 얻어야 하므로 클라이언트가 다른 사람의 ID를 요청 본문에 넣을 수 없게 합니다. 목록 응답(`BlogPostListItem`)에는 본문·사진 없이 제목·썸네일·작성자만, 상세 응답(`BlogPostDetail`)에는 사진을 `position` 순으로 포함합니다.

## selectinload로 N+1 조회 문제 해결하기

포스트 목록에서 각 포스트의 작성자를 접근할 때 포스트 수만큼 추가 조회가 생기지 않게 `selectinload()`로 관계 데이터를 미리 읽습니다.

```python
from sqlalchemy.orm import selectinload
from sqlmodel import select


@app.get('/posts', response_model=list[BlogPostListItem])
def list_posts(session: SessionDep) -> list[BlogPost]:
    statement = (
        select(BlogPost)
        .options(selectinload(BlogPost.author))
        .order_by(BlogPost.id.desc())
    )
    return session.exec(statement).all()
```

SQLModel의 `select()`와 `Session.exec()`에 SQLAlchemy ORM의 로딩 옵션을 함께 사용할 수 있습니다. 상세 페이지처럼 사진도 필요하면 `selectinload(BlogPost.images)`를 추가합니다. 관계 컬렉션의 기본 순서에 화면 규칙을 맡기지 않고, 상세 조회에서는 별도 쿼리로 `PostImage`를 `position` 순으로 읽습니다.
