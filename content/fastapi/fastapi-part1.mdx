---
title: "Part 1. 기초: 블로그 포스트 API 시작하기"
---

FastAPI는 HTTP 요청을 Python 함수로 받아 JSON으로 응답하는 웹 API 프레임워크입니다. 타입 힌트만으로 요청 검증, 직렬화, 자동 API 문서를 처리합니다. 이 노트에서는 블로그 포스트의 제목·본문·썸네일 URL을 다루는 CRUD API를 만들면서 FastAPI의 요청·응답 기초를 익힙니다.

## FastAPI 설치하고 첫 JSON 응답 만들기

블로그 API를 실행하고 자동 API 문서를 확인할 때 FastAPI와 SQLModel을 함께 설치합니다. SQLite는 Python에 포함되어 있어 로컬 학습용으로 별도 서버가 필요 없습니다.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install 'fastapi[standard]' sqlmodel
```

`FastAPI()` 인스턴스를 만들고 데코레이터로 경로를 등록하면 JSON 응답이 준비됩니다.

```python
from fastapi import FastAPI

app = FastAPI()


@app.get('/')
def home() -> dict:
    return {'message': '사진 블로그 API'}
```

```bash
fastapi dev blog.py
```

개발 서버가 실행되면 `http://localhost:8000`에서 JSON 응답을, `/docs`에서 자동 API 문서를 확인할 수 있습니다. `fastapi dev`는 코드 변경을 감지해 서버를 다시 시작합니다.

## 경로 매개변수로 포스트 식별하기

특정 포스트를 URL로 찾을 때 `{post_id}`처럼 경로 매개변수를 선언합니다. 함수 매개변수에 타입 힌트를 붙이면 FastAPI가 자동으로 변환하고 잘못된 타입은 422로 거절합니다.

```python
@app.get('/posts/{post_id}')
def get_post(post_id: int) -> dict:
    return {'post_id': post_id, 'title': f'포스트 {post_id}'}
```

```text
GET /posts/3    → 200 {"post_id":3,"title":"포스트 3"}
GET /posts/abc  → 422 검증 오류
```

경로 매개변수는 URL 경로의 일부이므로 항상 필수입니다. 선택적 조건은 다음 토픽의 쿼리 매개변수로 받습니다.

## 쿼리 매개변수와 Query로 목록 필터링하기

블로그 홈에서 포스트 일부만 보여 줄 때 `offset`과 `limit`을 쿼리 매개변수로 받습니다. `Query()`로 기본값과 허용 범위를 선언하면 자동 검증과 API 문서에 반영됩니다.

```python
from fastapi import Query


@app.get('/posts')
def list_posts(
    offset: int = 0,
    limit: int = Query(default=20, ge=1, le=100),
) -> dict:
    return {'offset': offset, 'limit': limit}
```

```text
GET /posts?limit=5        → 200 {"offset":0,"limit":5}
GET /posts?limit=999      → 422 검증 오류
```

경로 매개변수는 URL 경로(`/posts/3`)에, 쿼리 매개변수는 `?` 뒤(`?limit=5`)에 위치합니다. 경로에 없는 함수 매개변수는 자동으로 쿼리 매개변수가 됩니다.

## Pydantic 모델로 포스트 작성 요청 받기

클라이언트가 보낸 JSON 본문을 검증된 객체로 받을 때 Pydantic 모델(또는 `SQLModel`)을 매개변수 타입으로 선언합니다. 요청에는 ID를 받지 않고 서버가 생성하는 원칙을 지킵니다.

```python
from sqlmodel import SQLModel


class BlogPostCreate(SQLModel):
    title: str
    content: str
    thumbnail_url: str | None = None


@app.post('/posts', status_code=201)
def create_post(post: BlogPostCreate) -> dict:
    return {'id': 1, **post.model_dump()}
```

```json
{
  "title": "첫 포스트",
  "content": "블로그를 시작합니다.",
  "thumbnail_url": null
}
```

`status_code=201`은 리소스 생성 성공을 알립니다. 타입이 맞지 않거나 필수 필드가 빠지면 422 검증 오류가 자동으로 반환됩니다.

## response_model로 응답 필드 제한하기

테이블 모델에는 내부 필드가 있을 수 있으므로 응답에는 공개할 필드만 가진 별도 모델을 선언합니다. `response_model`은 반환 값에서 선언된 필드만 직렬화합니다.

```python
class BlogPostPublic(SQLModel):
    id: int
    title: str
    content: str
    thumbnail_url: str | None
```

```python
@app.get('/posts/{post_id}', response_model=BlogPostPublic)
def get_post(post_id: int) -> dict:
    return {'id': post_id, 'title': '제목', 'content': '본문', 'thumbnail_url': None, 'internal_flag': True}
```

응답 JSON에는 `internal_flag`가 포함되지 않습니다. 요청 모델(`BlogPostCreate`)과 응답 모델(`BlogPostPublic`)을 분리하면 API의 입출력 경계가 분명해집니다.

## HTTPException으로 오류 응답 보내기

존재하지 않는 포스트 ID를 요청했을 때 빈 성공 응답 대신 적절한 상태 코드와 메시지를 돌려줍니다. `raise HTTPException()`은 즉시 응답을 반환하고 함수 실행을 중단합니다.

```python
from fastapi import HTTPException

posts = {1: {'id': 1, 'title': '첫 포스트', 'content': '블로그를 시작합니다.'}}


@app.get('/posts/{post_id}')
def get_post(post_id: int) -> dict:
    if post_id not in posts:
        raise HTTPException(status_code=404, detail='포스트를 찾을 수 없습니다.')
    return posts[post_id]
```

```text
GET /posts/1    → 200 {"id":1,"title":"첫 포스트","content":"블로그를 시작합니다."}
GET /posts/999  → 404 {"detail":"포스트를 찾을 수 없습니다."}
```

성공 흐름은 `return`으로, 실패 흐름은 `HTTPException`으로 분리합니다. 이후 CRUD 토픽에서 데이터베이스 세션과 함께 사용하는 패턴을 확인합니다.

## Depends와 Session으로 요청마다 DB 세션 만들기

데이터베이스 연결처럼 반복되는 설정을 엔드포인트마다 작성하는 대신 의존성 함수로 분리합니다. `yield` 뒤에 세션이 닫히므로 각 요청이 독립된 세션을 사용합니다.

```python
from contextlib import asynccontextmanager
from typing import Annotated

from fastapi import Depends, FastAPI
from sqlmodel import Field, Session, SQLModel, create_engine

engine = create_engine('sqlite:///blog.db', connect_args={'check_same_thread': False})


@asynccontextmanager
async def lifespan(app: FastAPI):
    SQLModel.metadata.create_all(engine)
    yield


app = FastAPI(lifespan=lifespan)


def get_session():
    with Session(engine) as session:
        yield session


SessionDep = Annotated[Session, Depends(get_session)]
```

`Annotated[Session, Depends(get_session)]`을 `SessionDep`으로 별칭하면 이후 모든 엔드포인트에서 `session: SessionDep`으로 짧게 선언할 수 있습니다. `lifespan`은 앱 시작 시 테이블을 만들고, `create_engine()`은 SQLite 파일과 연결합니다.

## POST·GET·DELETE로 포스트 CRUD 완성하기

앞의 모든 개념을 조합해 블로그 포스트의 생성·목록·상세·삭제를 완성합니다. `BlogPost` 테이블 모델을 선언하고, 각 엔드포인트에서 `SessionDep`을 사용합니다.

```python
class BlogPost(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    title: str = Field(index=True)
    content: str
    thumbnail_url: str | None = None


@app.post('/posts', response_model=BlogPostPublic, status_code=201)
def create_post(post: BlogPostCreate, session: SessionDep) -> BlogPost:
    db_post = BlogPost.model_validate(post)
    session.add(db_post)
    session.commit()
    session.refresh(db_post)
    return db_post


@app.get('/posts', response_model=list[BlogPostPublic])
def list_posts(
    session: SessionDep,
    offset: int = 0,
    limit: int = Query(default=20, ge=1, le=100),
) -> list[BlogPost]:
    statement = select(BlogPost).order_by(BlogPost.id.desc()).offset(offset).limit(limit)
    return session.exec(statement).all()


@app.get('/posts/{post_id}', response_model=BlogPostPublic)
def get_post(post_id: int, session: SessionDep) -> BlogPost:
    post = session.get(BlogPost, post_id)
    if post is None:
        raise HTTPException(status_code=404, detail='포스트를 찾을 수 없습니다.')
    return post


@app.delete('/posts/{post_id}', status_code=204)
def delete_post(post_id: int, session: SessionDep) -> None:
    post = session.get(BlogPost, post_id)
    if post is None:
        raise HTTPException(status_code=404, detail='포스트를 찾을 수 없습니다.')
    session.delete(post)
    session.commit()
```

`commit()`으로 저장을 확정하고 `refresh()`로 데이터베이스가 만든 `id`를 다시 읽습니다. `session.delete()`만으로는 영구 반영되지 않으며 반드시 `commit()`이 필요합니다. 다음 Part에서 파일 업로드와 라우터 분리를 추가합니다.
