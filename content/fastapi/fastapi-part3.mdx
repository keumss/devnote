블로그 API가 커지면 수정·삭제 권한, 요청 전후 처리, 비동기 엔드포인트 선택, 에러 응답 일관성, 테스트 격리가 중요해집니다. 이 노트에서는 부분 수정, `BackgroundTasks`, 비동기 선택, 소유자 확인 의존성, 트랜잭션 관리, 미들웨어, CORS, 글로벌 예외 핸들러, `TestClient`를 다룹니다.

## exclude_unset으로 보낸 필드만 수정하기

제목만 바꾸는 PATCH 요청이 본문이나 썸네일을 기본값으로 덮어쓰지 않게 모든 수정 필드를 선택적으로 선언합니다. `model_dump(exclude_unset=True)`는 요청에 실제로 포함된 필드만 골라냅니다.

```python
from fastapi import HTTPException
from sqlmodel import SQLModel


class BlogPostUpdate(SQLModel):
    title: str | None = None
    content: str | None = None
    thumbnail_url: str | None = None


@app.patch('/posts/{post_id}', response_model=BlogPostPublic)
def update_post(post_id: int, patch: BlogPostUpdate, session: SessionDep) -> BlogPost:
    post = session.get(BlogPost, post_id)
    if post is None:
        raise HTTPException(status_code=404, detail='포스트를 찾을 수 없습니다.')
    post.sqlmodel_update(patch.model_dump(exclude_unset=True))
    session.add(post)
    session.commit()
    session.refresh(post)
    return post
```

`thumbnail_url: null`을 명시적으로 보내면 그 값은 포함되어 썸네일을 지울 수 있습니다. 반대로 해당 키 자체를 보내지 않으면 기존 값이 유지됩니다.

## BackgroundTasks로 업로드 후처리 분리하기

이미지 업로드 뒤 썸네일 생성 같은 후처리를 응답 반환 후에 실행할 때 `BackgroundTasks`를 사용합니다. 클라이언트는 후처리 완료를 기다리지 않고 즉시 응답을 받습니다.

```python
import logging
import shutil
from pathlib import Path

from fastapi import BackgroundTasks, UploadFile

logger = logging.getLogger(__name__)
UPLOAD_DIR = Path('uploads')


def generate_thumbnail(image_path: str) -> None:
    logger.info('썸네일 생성 시작: %s', image_path)
    # 실제로는 Pillow 등으로 리사이즈
    logger.info('썸네일 생성 완료: %s', image_path)


@app.post('/images', status_code=201)
async def upload_image(file: UploadFile, background_tasks: BackgroundTasks) -> dict:
    dest = UPLOAD_DIR / file.filename
    with dest.open('wb') as buf:
        shutil.copyfileobj(file.file, buf)
    background_tasks.add_task(generate_thumbnail, str(dest))
    return {'filename': file.filename, 'status': '업로드 완료, 썸네일 생성 중'}
```

`add_task()`에 함수와 인수를 전달하면 응답 전송 뒤 같은 프로세스에서 실행됩니다. 후처리가 실패해도 이미 반환된 응답에는 영향이 없습니다. 실패 처리가 중요하거나 작업 시간이 길면 Celery 같은 작업 큐를 검토합니다.

## async def와 def 엔드포인트 차이 이해하기

FastAPI에서 `def`와 `async def` 중 어느 것을 쓸지는 엔드포인트 안의 I/O 방식으로 결정합니다.

```python
# 동기 DB 작업 → def 사용
@app.get('/posts/{post_id}')
def get_post(post_id: int, session: SessionDep) -> BlogPost:
    return session.get(BlogPost, post_id)


# 비동기 외부 API 호출 → async def 사용
import httpx


@app.get('/external')
async def fetch_external() -> dict:
    async with httpx.AsyncClient() as client:
        response = await client.get('https://api.example.com/data')
        return response.json()
```

`def` 엔드포인트는 FastAPI가 자동으로 스레드 풀에서 실행해 이벤트 루프를 막지 않습니다. `async def` 안에서 동기 블로킹 코드(SQLModel 동기 세션, `time.sleep()` 등)를 실행하면 이벤트 루프가 멈춰 다른 요청이 대기합니다.

```python
# ⚠️ 잘못된 예: async def 안에서 동기 DB 호출
@app.get('/bad')
async def bad_example(session: SessionDep) -> BlogPost:
    return session.get(BlogPost, 1)  # 이벤트 루프를 블로킹
```

규칙: `await`할 것이 없으면 `def`를 사용합니다. SQLModel/SQLAlchemy 동기 세션은 `def`로 충분합니다.

## 작성자 의존성으로 소유자 확인하기

포스트 수정·삭제 전에 현재 작성자가 소유자인지 확인합니다. 학습용으로 `X-Author-Id` 헤더를 읽는 의존성을 만들고, 소유자 확인을 서비스 함수에 모아 PATCH·DELETE·사진 API가 같은 규칙을 재사용합니다.

```python
from typing import Annotated

from fastapi import Depends, Request


def get_current_author(request: Request, session: SessionDep) -> Author:
    author_id_text = request.headers.get('X-Author-Id')
    if author_id_text is None or not author_id_text.isdecimal():
        raise HTTPException(status_code=401, detail='로그인이 필요합니다.')
    author = session.get(Author, int(author_id_text))
    if author is None:
        raise HTTPException(status_code=401, detail='작성자를 찾을 수 없습니다.')
    return author


CurrentAuthor = Annotated[Author, Depends(get_current_author)]


def get_owned_post(post_id: int, author_id: int, session: Session) -> BlogPost:
    post = session.get(BlogPost, post_id)
    if post is None:
        raise HTTPException(status_code=404, detail='포스트를 찾을 수 없습니다.')
    if post.author_id != author_id:
        raise HTTPException(status_code=403, detail='수정 권한이 없습니다.')
    return post
```

실제 서비스에서는 검증된 JWT 토큰이나 세션에서 작성자 ID를 얻어야 하며, 클라이언트가 보낸 임의 ID를 신뢰하면 안 됩니다. 404와 403을 구분하면 클라이언트는 존재하지 않는 리소스와 권한 없는 리소스를 다르게 처리할 수 있습니다.

## Session.begin으로 사진 교체를 트랜잭션으로 묶기

본문 사진 전체를 새 배열로 교체할 때 기존 사진 삭제와 새 사진 삽입이 함께 성공해야 합니다. `session.begin()` 블록에서 작업하면 예외 발생 시 자동으로 롤백됩니다.

```python
from sqlmodel import Session, select


def replace_images(post_id: int, new_images: list[PostImageCreate], session: Session) -> None:
    with session.begin():
        post = session.get(BlogPost, post_id)
        if post is None:
            raise HTTPException(status_code=404, detail='포스트를 찾을 수 없습니다.')
        old_images = session.exec(
            select(PostImage).where(PostImage.post_id == post_id)
        ).all()
        for image in old_images:
            session.delete(image)
        session.add_all([
            PostImage(post_id=post_id, url=img.url, alt_text=img.alt_text, position=idx)
            for idx, img in enumerate(new_images, start=1)
        ])
```

`begin()` 블록 안에서는 `commit()`을 직접 호출하지 않습니다. 블록이 정상 종료되면 커밋되고, 예외가 전파되면 롤백됩니다. 조회도 블록 안에서 시작해 이미 열린 트랜잭션과 충돌하지 않게 합니다.

## 미들웨어로 요청 처리 시간 기록하기

모든 요청의 응답 시간을 측정해 헤더에 넣을 때 미들웨어를 사용합니다. 미들웨어는 모든 요청이 엔드포인트에 도달하기 전과 응답이 반환된 후에 실행됩니다.

```python
import time

from starlette.requests import Request
from starlette.responses import Response


@app.middleware('http')
async def add_process_time_header(request: Request, call_next) -> Response:
    start = time.perf_counter()
    response = await call_next(request)
    elapsed = time.perf_counter() - start
    response.headers['X-Process-Time'] = f'{elapsed:.4f}'
    return response
```

```text
GET /posts → 200, X-Process-Time: 0.0023
```

미들웨어는 **모든 요청**에 적용됩니다. 특정 경로에만 필요한 로직은 `Depends`로 의존성을 만드는 것이 적합합니다.

| 구분 | 미들웨어 | 의존성(Depends) |
|------|---------|----------------|
| 적용 범위 | 모든 요청 | 선언한 엔드포인트만 |
| 응답 접근 | 가능 (response 가로채기) | 불가 |
| 요청 데이터 접근 | Request 객체 | 경로·쿼리·본문 매개변수 |
| 활용 예 | 로깅, CORS, 타이밍 | 인증, DB 세션, 페이지네이션 |

## CORSMiddleware로 프론트엔드 접근 허용하기

블로그 프론트엔드(`http://localhost:3000`)가 API(`http://localhost:8000`)에 요청하면 브라우저가 출처가 다르다며 차단합니다. `CORSMiddleware`로 허용할 출처·메서드·헤더를 설정합니다.

```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI()

app.add_middleware(
    CORSMiddleware,
    allow_origins=['http://localhost:3000'],
    allow_credentials=True,
    allow_methods=['*'],
    allow_headers=['*'],
)
```

```text
프론트엔드 http://localhost:3000 → OPTIONS /posts → 200 (preflight 허용)
프론트엔드 http://localhost:3000 → GET /posts     → 200 (본 요청 허용)
```

`allow_origins`에 허용할 출처를 명시합니다. `'*'`는 모든 출처를 허용하므로 개발 단계에서만 사용하고, 운영 환경에서는 실제 도메인만 등록합니다. CORS 미들웨어는 다른 미들웨어보다 먼저 등록해야 preflight OPTIONS 요청이 올바르게 처리됩니다.

## 글로벌 예외 핸들러로 에러 응답 통일하기

`HTTPException`만으로는 API 전체의 에러 응답 형식을 통일하기 어렵습니다. 비즈니스 예외 클래스를 정의하고 `@app.exception_handler`로 일관된 에러 응답을 만듭니다.

```python
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse


app = FastAPI()


class BlogError(Exception):
    def __init__(self, code: str, detail: str, status_code: int = 400):
        self.code = code
        self.detail = detail
        self.status_code = status_code


class PostNotFoundError(BlogError):
    def __init__(self, post_id: int):
        super().__init__(
            code='post_not_found',
            detail=f'포스트 {post_id}를 찾을 수 없습니다.',
            status_code=404,
        )


class NotPostOwnerError(BlogError):
    def __init__(self):
        super().__init__(
            code='not_post_owner',
            detail='수정 권한이 없습니다.',
            status_code=403,
        )


@app.exception_handler(BlogError)
async def blog_error_handler(request: Request, exc: BlogError) -> JSONResponse:
    return JSONResponse(
        status_code=exc.status_code,
        content={'error': exc.code, 'detail': exc.detail},
    )
```

```python
@app.get('/posts/{post_id}')
def get_post(post_id: int, session: SessionDep) -> BlogPost:
    post = session.get(BlogPost, post_id)
    if post is None:
        raise PostNotFoundError(post_id)
    return post
```

```text
GET /posts/999
404 {"error":"post_not_found","detail":"포스트 999를 찾을 수 없습니다."}
```

비즈니스 예외를 정의하면 엔드포인트 코드는 비즈니스 로직에만 집중하고, 에러 응답 형식은 핸들러 한 곳에서 관리합니다. `HTTPException`은 단순 에러에, 커스텀 예외는 도메인별 에러 코드가 필요할 때 사용합니다.

## dependency_overrides와 TestClient로 API 테스트하기

API 테스트가 개발용 데이터베이스를 건드리지 않게 `get_session` 의존성을 테스트 전용 메모리 데이터베이스로 교체합니다.

```python
from fastapi.testclient import TestClient
from sqlalchemy.pool import StaticPool
from sqlmodel import Session, create_engine

test_engine = create_engine(
    'sqlite://',
    connect_args={'check_same_thread': False},
    poolclass=StaticPool,
)
SQLModel.metadata.create_all(test_engine)


def get_test_session():
    with Session(test_engine) as session:
        yield session


app.dependency_overrides[get_session] = get_test_session
client = TestClient(app)
```

`StaticPool`은 테스트 클라이언트와 요청 세션이 같은 메모리 SQLite 연결을 사용하게 합니다. 이제 성공·실패 흐름을 테스트합니다.

```python
def test_update_rejects_another_authors_post() -> None:
    with Session(test_engine) as session:
        owner = Author(name='민지')
        other = Author(id=999, name='도윤')
        post = BlogPost(title='비공개 초안', content='본문', author=owner)
        session.add_all([other, post])
        session.commit()
        session.refresh(post)

    response = client.patch(
        f'/posts/{post.id}',
        json={'title': '바꿀 수 없는 제목'},
        headers={'X-Author-Id': '999'},
    )
    assert response.status_code == 403
```

권한 실패를 테스트하면 모델 갱신 코드가 소유권 규칙을 우회하지 않는지 확인할 수 있습니다. 테스트가 끝나면 `app.dependency_overrides.clear()`로 교체를 해제합니다.
